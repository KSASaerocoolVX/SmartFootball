# Прикладная логика SmartFootball

## Архитектура

Слой `src/logic` использует существующие `Player` и `Team` из `src/model`. Он работает с `std::vector<Player>` и `QString` из Qt Core. Элементы интерфейса передают действия в `ScoutController` и читают результат для отображения.

| Класс | Назначение |
| --- | --- |
| `ICommand` | Абстрактный интерфейс с виртуальным деструктором. Метод `execute(const std::vector<Player>&)` читает входную коллекцию и возвращает новый вектор игроков. |
| `ScoutController` | Хранит исходный список и текущий результат. Передаёт текущий результат очередной команде и сохраняет возвращённый вектор. |
| `FindCommand` | Ищет полное имя или его фрагмент через `QString::contains` без учёта регистра. Убирает пробелы с краёв запроса. Пустой запрос сохраняет текущий список. |
| `FilterCommand` | Отбирает игроков по `teamId` и позициям `GK`, `DEF`, `MID`, `FWD`. Заданные критерии должны выполняться одновременно. Сравнение позиций учитывает пробелы с краёв и игнорирует регистр. |
| `SortCommand` | Сортирует по имени, рейтингу, стоимости (`marketValueM`), голам или ассистам в обоих направлениях. Сравнивает имена без учёта регистра. |

Каждое действие представлено отдельной командой. Для новой операции достаточно реализовать `ICommand` и передать объект команды в контроллер. Поиск и фильтрация используют `std::copy_if` со `std::back_inserter`. Сортировка использует `std::stable_sort`, поэтому при равных ключах сохраняется порядок текущего списка. Значения `NaN` в рейтинге и стоимости помещаются в конец в обоих направлениях.

## Интерфейс ScoutController

| Метод | Поведение |
| --- | --- |
| `ScoutController(players)` | Сохраняет снимок переданной коллекции. Конструктор без аргументов создаёт пустой список. |
| `setPlayers(players)` | Заменяет исходный список и текущий результат, например после загрузки данных. |
| `players() const` | Возвращает текущий результат без выполнения команды. |
| `find(query)` | Выполняет поиск по текущему списку. |
| `filter(teamId, position)` | Применяет фильтры к текущему списку. `std::nullopt` отключает критерий клуба, пустая строка отключает критерий позиции. |
| `sort(field, order)` | Сортирует текущий список. Направление по умолчанию — `SortOrder::Ascending`. |
| `execute(command)` | Выполняет произвольную команду `ICommand` над текущим списком. |
| `reset()` | Восстанавливает полный исходный список в исходном порядке. |

Некорректный ID клуба, неизвестная непустая позиция и некорректные параметры сортировки вызывают `std::invalid_argument`. ID и позицию проверяют существующие методы `Team::isValidId` и `Player::isValidPosition`. Корректный ID без совпадений даёт пустой результат. При ошибке параметров текущий результат сохраняется.

Методы, которые возвращают список, дают `const std::vector<Player>&`. Читайте его непосредственно для заполнения таблицы. Если результат нужен независимо от дальнейших операций контроллера, скопируйте вектор. После изменения результата заново получайте ссылки на элементы и итераторы.

```cpp
#include "logic/ScoutController.h"

void showMidfielders(const std::vector<Player>& leaguePlayers) {
    ScoutController scout(leaguePlayers);
    scout.find(QStringLiteral("иван"));
    scout.filter(11, QStringLiteral("MID"));
    const auto& rows = scout.sort(SortField::Rating, SortOrder::Descending);
    for (const Player& player : rows) {
        // Передать player в таблицу.
    }

    scout.reset();  // Восстановить полный список перед новым запросом.
    scout.filter(std::nullopt, QStringLiteral("GK"));
}
```

## Подключение MainWindow и LeagueRepository

1. Добавьте `ScoutController` в качестве поля `MainWindow` и после загрузки передайте список в `setPlayers`.
2. При изменении параметров поиска или фильтра таблицы вызовите `reset()`, затем примените актуальные критерии через `find`, `filter` и `sort`. Так расширение критериев снова покажет строки из исходного списка.
3. Заполняйте таблицу из `players()`. Для сброса воспользуйтесь `reset()` и обновите таблицу. При `std::invalid_argument` отобразите сообщение об ошибке параметров.

Когда появится `LeagueRepository`, возьмите из него полный список игроков через согласованный интерфейс команды и передайте его в конструктор контроллера или `setPlayers`. При обновлении данных повторите `setPlayers` и при необходимости примените активные критерии окна. Репозиторий отвечает за данные лиги, контроллер — за выборку для отображения.

## Сборка и проверки

Для сборки на Windows нужны Qt5 Core и Widgets, совместимый компилятор с C++17 и CMake. Для MinGW-комплекта Qt 5.15.2 добавьте в `PATH` каталоги `bin` Qt и MinGW, затем укажите путь к Qt при конфигурации.

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH="C:/Qt/5.15.2/mingw81_64"
cmake --build build
```

На Windows успешно собрана цель `smartfootball` в конфигурации Release с CMake 4.2.0, MinGW 8.1.0 и Qt 5.15.2. Отдельный временный стенд, собранный с теми же исходниками логики и Qt Core, прошёл 36 проверок.

- Поиск полного имени и фрагмента кириллического имени без учёта регистра, пустой запрос и отсутствие совпадений.
- Фильтрация по клубу, по позиции и по обоим критериям. Сброс восстанавливает полный список.
- Сортировка по всем пяти ключам, оба направления для рейтинга и стоимости, сохранение порядка при равных рейтингах и обработка `NaN`.
- Пустой список, последовательность «поиск → фильтр → сортировка», сохранность исходных данных, замена списка и выполнение дополнительной команды через `ICommand`.
- Отклонение недопустимых ID, позиции, ключа и направления сортировки с сохранением текущего результата.
